# Protocol v2: timing, participation and resource allowances

## Problem & constraints

The approved scope is cumulative player time, clock snapshots, fixed phase deadlines,
trusted expiry causes, player lifecycle, replay accounting, versioned envelopes/capabilities,
and named resource allowances. Existing three agent operations remain. No dependencies.
Historical v1 configurations, logs and game implementations retain their semantics.
Current games migrate to v2; chess uses a 600000ms player total with no decision cap.

## States and semantics

- Protocol v2/runtime 0.2.0; retain protocol v1/runtime 0.1.0 execution and readers.
  Unknown versions, capabilities, fields and malformed policies fail admission/validation.
- `TimingPolicy`: `playerTotalMs: number|null`, `decisionLimitMs: number|null`,
  `phaseLimits: Record<string, {durationMs:number; close:"ready_or_deadline"|"deadline"}>`,
  `clockVisibility: "private"|"public"`. Durations are positive safe-integer milliseconds;
  null disables a constraint, an empty phase map disables phase deadlines. No increments.
- `ResourceAllowance`: `{amount:number; reset:"match"|"phase"|"decision";
  visibility:"private"|"public"}`. Named keys use lowercase ASCII identifiers with underscores;
  reject prototype keys, empty names, unknown resets, fractional, unsafe, nonfinite or negative amounts/costs.
  `ResourceAllowances` is a record of definitions. No game-specific keys in v2 runtime.
- `MeteringPolicy`: optional `action` and `invalidAction`, each `{resource:string;cost:number}`.
  Amounts, balances and costs are nonnegative safe-integer units; fractional legacy budgets
  retain their original v1 behavior. References must name declared resources. Action metering applies to schema-valid game calls;
  sensing declares its own `resource` and cost. Invalid metering applies only to semantic
  rejection; if its remaining allowance cannot pay, apply the declared safe default once.
  Schema-invalid calls and unknown tools do not spend resources. All consume active elapsed time.
- V2 configuration has `timing`, `resources`, `metering`; v1 has historical `budgets`.
  V2 manifests have `defaultTiming`, `defaultResources`, `defaultMetering`; v1 retains
  `defaultBudgets`. Separate legacy types keep old names out of the current authoring API.
- Allowances start at amount. Match allowances never reset; phase allowances reset on a new
  epoch, including a repeated phase name; decision allowances reset after accepted game actions.
  Polling/sensing/rejections do not reset them. Zero is exhausted, not unlimited.
- `Participation` is `{status:"acting"|"waiting"}` or `{status:"finished";reason:string}`.
  Optional plugin `participation(state,seat)` defaults to acting when non-sensing offers exist,
  waiting otherwise, finished at match terminal. Finished is permanent within that match.
- `phaseId` is the match/phase epoch identity, stable across actions in the same phase.
  Every phase occurrence may own one deadline. A deadline-only phase waits even when ready;
  ready-or-deadline can close early. A zero-action phase can progress through expiry.
- Each acting seat spends elapsed time, concurrently when several act. Waiting/finished seats
  spend none. Total allowance never renews. Earliest active limit wins; expiry wins at equality.
  Sensing, invalid actions, retries and polls do not reset clocks. Host uses a monotonic clock
  mapped to epoch milliseconds; injected clocks support deterministic tests.
- `ClockSnapshot`: `{sampledAt,remainingMs,running,deadline,phaseId,phaseDeadline}` where
  remaining/deadlines may be null. Observations expose own snapshot; public clocks appear
  only under public clock visibility. Never disclose hidden participation through metadata.
- `HostEvent`: `{kind:"decision_expired"|"player_time_exhausted"|"phase_expired"|
  "invalid_retries_exhausted";seats:string[];phaseId:string;at:number}`. Due seats at one instant
  form one deterministic batch, ordered by seat; total exhaustion precedes phase then decision.
  Optional plugin `onHostEvent(state,event)` applies game-owned state changes atomically.
  Ordinary decision/retry expiry can use existing safe defaults; player-total configuration
  requires an exhaustion handler. Exhausted seats must become finished or match terminal;
  violations abort, never spin defaults. Phase expiry applies pending defaults then resolves,
  or the plugin handles it; no actor action is required to trigger a timed phase.
- Results add an optional structured cause `{kind:string; detail?:string; seats?:string[]}`;
  v2 games supply it. Clock timeout and voluntary resignation are distinct game outcomes.
- Shared v2 next messages: turn, waiting, seat_finished, match_over, match_aborted, idle.
  `waiting` has no game decision but may retain sensing offers; idle is unassigned/acknowledged. seat_finished
  is acknowledged independently of whole-match terminal. No new MCP tools.
- V2 runtime logs trusted commands plus derived events; replay re-executes deterministic
  commands with recorded timestamps and compares the complete regenerated log and outcomes.
  It validates recorded accounting, not physical truth of the host clock. No real-time/LLM calls.
  V1 replays retain their original verification path. Unknown v2 commands/events fail verification.
- V2 tournament scheduling returns `{config,seed,seedIndex,assignments}` records; scheduling
  metadata stays outside strict game rules. Historical scheduling keeps its old shape.
- Capability response advertises supported protocol versions and v2 timing/lifecycle/resource
  features. Configurations pin identity and policy; clients validate shared versioned envelopes.
  Active sessions still abort across host restart; this change does not add durable resumption.

## Threat model

Agents control tool/input/request identities, never host events or clock values. Host ingress
accepts only agent commands. Negative costs cannot mint resources. Retries are deduplicated before
execution. Finished seats cannot regain offers. Public projections cannot reveal private clocks,
resource balances or participation. Logs/frames are full-disclosure only after terminal.

## Mechanism

- `packages/protocol/src/`: v2 contracts and validation, legacy compatibility types.
- `packages/core/src/`: named allowance accounting and legacy helpers.
- `packages/referee/src/`: deterministic v2 reducer, timing, participation and exact replay;
  preserve a separate v1 reducer path to avoid reinterpreting historical execution.
- `packages/host/src/`: policy admission, monotonic clock delivery, both runners and HTTP.
- `packages/client/src/`, `packages/schemas/src/`, `packages/viewer/src/`: shared envelopes,
  lifecycle handling and privacy-aware clocks/resources in generic presentation.
- `games/`: retain current v1 revisions under `legacy-v1`; migrate current plugins and tests.

## Rejected alternatives

- Chess-specific time controls: player total is a general match constraint.
- Reusing decisionId for phase timers: accepted discussion actions change it.
- Renaming fixed budget keys: new games would still need runtime changes for every resource.
- Replacing old replay semantics: changes the interpretation of published artifacts.

## Blast radius & rollback

Contract, runtime, game defaults, adapters, clients and replay change together. No DB migration.
Rollback source alone cannot execute newly written v2 artifacts; retain v2 runtime when serving
those artifacts. V1 artifacts retain frozen games and their original reducer/verifier.

## Test plan

Forbid time renewal through retries/actions; charging waiting seats; negative/malformed resource
costs; wrong reset scope; hidden timing leakage; late actions winning expiry; order-dependent
simultaneous expiry; zero-time default loops; premature/renewed phase cutoffs; missed seat-finished
notifications; forged host events; unsupported-version admission; replay tampering in commands,
charges, timing and result; and reinterpretation of v1 artifacts. Exercise both runners, HTTP,
MCP/client lifecycle, generic viewer, current catalog conformance and historical fixtures.
