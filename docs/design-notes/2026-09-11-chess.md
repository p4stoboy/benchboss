# Chess for agents

This note specifies retained revision `1.0.0`. Current revision `2.0.0` adopts the
[protocol v2 design](2026-09-11-protocol-v2.md), including cumulative player clocks
and named resource allowances. The board rules below remain the same.

## Problem & constraints

Add two-agent chess to the current public catalog without changing protocol v1,
host policy, historical games or the generic spectator renderer. Execution is
pure, deterministic and serializable; source remains MIT, with no external rules
dependency. The new workspace uses existing `@benchboss/core`,
`@benchboss/protocol` and `@benchboss/referee` contracts.

## States and semantics

- Game ID `chess`, revision `1.0.0`, exactly two distinct seats. Seeded seat
  shuffling assigns White/Black once; White moves first from the normal position.
- Rules: optional `maxPlies`, integer 1..1000, default 600. Unknown rules fail.
  A ply is one move by one player. Hosts snapshot this rule and all budgets.
- Phase `move`: only the side to move may act, and only once before resolution.
  Accepted input becomes a pending action; resolution applies it and renews the
  decision epoch even when the next phase is also `move`. Terminal has no offers.
- `match.move`: exactly `{move: string}`; lowercase UCI source/destination and
  mandatory `q`, `r`, `b` or `n` suffix for promotions. The schema enumerates all
  currently legal moves. Castling uses the king's destination, e.g. `e1g1`.
- `match.resign`: exactly `{}`. Only the acting seat can resign. The safe default
  is this exact tool/input; expiry or exhausted semantic retries forfeits the game.
  Default budget: 90 seconds, one action per decision, one invalid retry, no sensing.
- Unknown seat/tool, malformed input, self-check and illegal moves are rejected.
  The module also validates directly because replay calls `submit` without referee
  validation. Missing tool identity is rejected for this new revision.
- Outcome precedence after a move: checkmate, stalemate, insufficient material,
  automatic threefold repetition, automatic 100 quiet plies, configured ply limit.
  Checkmate wins even on the ply/quiet-move boundary. Resignation awards the opponent
  a win. Win/loss scores are 1/0; drawn seats score 0.5 and share first place.
- Insufficient material means bare kings, king + one bishop/knight versus king,
  or only kings and bishops with every bishop on the same square color. Other dead
  positions are bounded by repetition/quiet-move/ply rules; no general dead-position
  search. Draw claims/offers, total match clocks and Chess960 are outside revision 1.
- Repetition includes placement, side, castling rights and en passant only when a
  legal en-passant capture exists; quiet counters/fullmove numbers do not count.
- Observations expose the complete board (FEN and ranked rows), colors, turn,
  legal UCI moves, check, move history and outcome. Private state is empty.
  Public views use shared participant/table/text/list blocks, never seed/config.
  Spectator move lists retain the latest 40 plies; agent observations and execution
  logs retain all moves. Frame sizes stay within generic viewer/process limits.
  A submitted move is exposed after resolution; terminal metadata remains host-owned.

## Threat model

Agent tool names and inputs are untrusted. Schema checks and independent module
validation reject illegal commands without mutating prior state. No executable
input, remote engines, file access, arbitrary positions or agent-selected colors.
All board information is public; the seed is excluded from projections.

## Mechanism

`games/chess/src/position.ts` owns immutable board transitions, legal move generation,
check, special moves, FEN and repetition identity. `game.ts` owns adjudication,
observations and pending decisions; `plugin.ts` supplies the manifest, explicit
default and public projector. `games/catalog.ts` registers the revision. Tests use
known perft totals, adversarial legal positions and real referee/host execution.

## Rejected alternatives

- A game-specific MCP tool/server or viewer: the existing dispatcher and table
  blocks already express chess and preserve the agents-only boundary.
- A class-based rules dependency: conflicts with the repository's functional
  TypeScript rule. A GPL dependency would also change source-consumer obligations.
- Automatically playing a legal move on expiry: masks agent failure and invents
  strategy; resignation makes the consequence explicit and finishes silent matches.

## Blast radius & rollback

New games become discoverable to hosts using the current catalog. Existing games,
protocol fields and legacy revisions are unchanged. Removing chess from new-match
selection rolls back admission; hosts retaining chess artifacts must retain this
revision for replay. Official deployment is a separate source-release action.

## Test plan

Forbid incorrect move trees with independent published perft counts. Forbid castling
through check, stale en passant, self-check, king capture and missing promotion.
Prove terminal priority, repetitions with effective en passant, quiet-counter resets,
immutability and generated legal-play invariants. Exercise exact tool validation,
inactive-seat rejection, decision renewal, expiry, explicit outcomes, terminal
replay/tamper rejection and generic rendering. Run catalog conformance and repository
checks, then complete a loopback HTTP match with two scripted agents.
